**Decisions made:**

- **Pivoted from Claude Agent SDK to direct `anthropic` SDK.** The `claude-agent-sdk` package isn't on PyPI under that name. Direct API is cleaner anyway (fewer deps, full control), and it sidesteps the Claude Code permissions layer entirely — which neatly resolves the original "permission prompts during audits" concern: when there's no Claude Code in the loop, there are no prompts.
- **Local-first GUI, deferred deployment.** No Render service, no domain, no auth. Personal tool, single user, runs on the operator's Mac. Deployment can be added later if multi-user or remote access becomes a real need.
- **No cost-ceiling abort mid-audit.** User correctly pushed back on this proposal during the runaway-cost-meter incident. Mid-audit aborts waste partial work and force full re-runs. Manual cancel button + correct cost meter + post-Phase-1 estimate is the right shape.
- **Hard rule: self-contained audits.** No cross-audit references in deliverables. `tools/qa.py` enforces with regex pattern matching. Sibling-bin brand-name leakage check uses a generic-token stop-list (`example`, `test`, `demo`, etc.) so smoke-test bins don't false-positive against ordinary prose in real audits.
- **Bins are gitignored, tool is committed.** The repo ships the engine, not the products. Each per-audit deliverable bin is a private artifact for the operator (or eventual client).
- **No backlog inflation in response to a small concern.** When user flagged $1.02 actual vs my $0.30 estimate as a possible "leak," I initially proposed a 4-part forensics build. User correctly called this gold-plating. Walked back to one item (post-Phase-1 estimator), which is what shipped. **Lesson: stay tight to scope, don't pad responses to look diligent.**
