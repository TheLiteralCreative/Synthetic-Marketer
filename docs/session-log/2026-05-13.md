**Decisions made:**

- **Active-Audits and Legacy-Audits live as siblings of the configured `output_folder`, not inside it as a child of the bins.** I.e., the directory layout is `<output_folder>/Active-Audits/<bin>` and `<output_folder>/Legacy-Audits/<bin>_<N>`, not `<output_folder>/<bin>/Active/`. Reason: matches operator's mental model (folders ARE the active/legacy demarcation, not a sub-property of each bin). Also keeps the GUI's bin-list logic clean — it just globs one directory, doesn't have to look inside each bin.

- **Brand match for Active→Legacy demotion is case-insensitive on the brand token only.** The date and any trailing `_<N>` iteration suffix are ignored. Reason: a re-audit of the same brand should be detected as a re-audit even if the operator typed the brand with different casing in the GUI form. The two existing Legacy folders left from manual operator triage (`Synth-mkt_CAPSTONE_20260413`, `Synth-mkt_FlexentFreight_20260506`) were retroactively normalized to `_1` suffix during the migration so the iteration counter gives consistent results going forward. (Operator chose the "normalize too" option when asked.)

- **GUI's "Past audits" view shows Active only — Legacy is archive-only.** Operator chose this option when asked. Cleaner default; Legacy folders remain accessible via Finder.

- **The QA pass remains numbered Phase 6 in the GUI even though it now also runs after Phase 8.** Reason: changing the phase numbering would mean updating frontend hardcoded phase labels (`frontend/src/components/PhaseTimeline.jsx`) — out of scope for a bug fix. The Phase 6 progress event re-emits with the corrected status after the silent re-run, so the GUI's final phase status accurately reflects the post-PDF QA result.
